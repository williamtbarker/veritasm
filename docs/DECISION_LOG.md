# Frozen baseline decision log

This log contains only decisions established by the Virustic2 audit at commit
`b211915fc7cce82629766b77024463c6cabcc749`. Research and architecture decisions belong in ADRs and
must not be inferred from this file. A frozen decision changes only when contrary evidence is recorded
in a superseding ADR.

| ID | Frozen decision | Evidence and consequence |
|---|---|---|
| BL-001 | Virustic2 commit `b211915fc7cce82629766b77024463c6cabcc749` is the sole compatibility and benchmark baseline. | The commit was fully audited and its deterministic benchmark artifacts reproduced. Later Virustic2 documentation or code cannot silently redefine the baseline. |
| BL-002 | Preserve plain and content-detected gzip FASTA/FASTQ, wrapped records, concatenated gzip members, single-end input, paired input, ordered multiple lanes, and one-use stdin. | Code inspection plus 31 passing tests confirmed these behaviors. Virustic3 may replace the parser implementation only with compatibility tests. |
| BL-003 | Preserve both support modes, but define them exactly as record-instance quantities. | Fragment mode deduplicates a canonical k-mer within one supplied read or record pair; occurrence mode counts accepted windows. Neither quantity proves independently sampled molecules. |
| BL-004 | `support`, `coverage`, `depth`, and `frequency` are not interchangeable. | Virustic2 stores per-k-mer record/window support and does not reconstruct positional read depth or allele frequency. Virustic3 reports each quantity under its own definition. |
| BL-005 | Preserve deterministic biological output through ordered reductions, canonical orientation/rotation, and sorting at stable boundaries. | The published one- and four-thread FASTA SHA-256 reproduced identically, and 1,000 random k=3 graph probes conserved canonical edges. Hash-map iteration order may not reach serialized output. |
| BL-006 | Preserve ambiguity as an explicit graph boundary rather than inventing a traversal. | Virustic2 stops at reverse-complement-palindromic `(k-1)` nodes and emits branches as unitigs. Virustic3 may resolve a path only when separately reported evidence supports it. |
| BL-007 | Keep exact database-free unitig extraction available as a useful conservative result. | Virustic2 demonstrably emits deterministic maximal nonbranching paths without references. A unitig is not, by itself, a consensus genome or haplotype. |
| BL-008 | Virustic2 pair identifier validation is not an acceptable inherited implementation. | Reversed `/1` and `/2`, duplicate CASAVA mate roles, and one physical file through lexical aliases were accepted. Virustic3 validates fragment identity, mate role, file pairing, and cardinality as separate invariants. |
| BL-009 | Atomicity is defined over the complete requested output bundle. | Virustic2 commits FASTA before JSON; a report failure replaced an existing FASTA. Virustic3 must leave every pre-existing requested artifact unchanged when the command returns failure. |
| BL-010 | Destination collision checks must work before destinations exist. | A `..` alias allowed JSON to overwrite FASTA while the command returned success. Lexical equality plus canonicalization of existing paths is insufficient. |
| BL-011 | A closed de Bruijn-graph cycle is only a circular candidate. | Virustic2's `circular` flag is derived from graph topology without a read-supported closing-junction audit. Molecular circularity requires explicit evidence and limitations. |
| BL-012 | Counting saturation must never be silent. | Virustic2 saturates `u32` edge counts without telemetry. Virustic3 widens the representation or returns/reports a specific saturation condition. |
| BL-013 | Streaming input is not evidence of bounded whole-run memory. | Virustic2 retains all distinct observed k-mers before cleaning and materializes complete records and batches. Memory claims require measured end-to-end bounds or a documented early-failure/partitioning mechanism. |
| BL-014 | Quality-threshold filtering remains a compatibility mode; it must not be described as quality-weighted counting. | Virustic2 rejects windows containing a base below the selected Phred+33 threshold, then gives every accepted k-mer equal weight. Any weighted model needs new validation. |
| BL-015 | Rust 1.85 is the starting Virustic3 MSRV floor until a superseding ADR provides evidence for a change. | Virustic2 declares 1.85 and all locked targets/tests passed with 1.85 during Gate 0. Current-stable success alone cannot raise the MSRV. |
| BL-016 | Retain typed library errors and add input role, lane, path, record, and position context at the presentation boundary. | Virustic2 cleanly separates typed FASTX/DNA/pipeline errors, but invalid-DNA errors can identify only the record ID. More context is required for multi-lane operational diagnosis. |
| BL-017 | Do not make an assembler-accuracy claim from the Virustic2 development benchmark. | Gate 0 reproduced its input/output hashes and throughput behavior, but it contains one synthetic generator, no truth metric, and no independent v1 rerun. It is a performance regression fixture only. |
| BL-018 | Preserve no-application-network runtime behavior and the absence of mandatory Python, Java, or Conda. | Static inspection found no network implementation; the release binary used only native system runtime libraries on Linux. Future dependencies require an explicit necessity, license, advisory, MSRV, and runtime-I/O review. |
| BL-019 | Every V2-D01 through V2-D10 observation in Gate 0 becomes a regression or limitation test before the compatibility gate can pass. | The original suite did not cover these counterexamples. Documentation alone is not proof that Virustic3 corrected them. |
| BL-020 | Virustic2's even-k reverse-complement handling is not a correct compaction oracle around a self-complemental k-mer. | The read `TCGCGAC` at `k=6` reproducibly yields an 8-base, three-step path backed by only two canonical keys. VeritAsm inherited the same behavior. ADR 0010 supersedes BL-006 and BL-007 only for this fixed-edge case: self-complemental-edge incidence is a hard compaction boundary, and exact adjacencies remain in GFA. |
